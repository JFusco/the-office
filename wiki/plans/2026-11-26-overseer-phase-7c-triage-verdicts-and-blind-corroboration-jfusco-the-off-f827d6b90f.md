- [ ] **Define verdict version 1 in `src/contracts/overseer.ts`.** Export `TRIAGE_VERDICTS`, `TriageResult` and its Zod 4.6.7 schema. Use `strictObject` at every object boundary and discriminate on `harness-defect`, `real-block`, `false-positive`, `stale-state` and `needs-joe`. Include version, confidence (`low`, `medium` or `high`), source and episode/event references, causal explanation and nullable `authorityPrerequisite`. Bound strings and lists, require nonblank narrative text, lowercase 64-hex hashes, repository-relative paths and unique set members. Limit paths to 300 characters and line numbers to 1 through 1,000,000. Allow references to all 50 included subjects and 30 recent events.

  A file reference contains path and file SHA-256. A `SourceRange` adds one-based inclusive start and end lines, a decisive line inside the interval and an excerpt SHA-256. A subject reference identifies its kind, key and stop digest. An event reference identifies its kind and event ID.

  A `harness-defect` identifies the runtime refusal site, the violated invariant and its distinct requirement citation, the cause, the smallest correction, the affected files and a concrete regression case. The correction contains its direction, site, versioned edit paths, explanation and structured case. The case names the covered episodes, the triggering clause or example, typed facts and scope, the observed refusal and the required disposition. Represent a disposition as `allow` or `refuse` with the applicable cause. Distinguish an unconditional rule from a conditional exception. Require the correction site in the edit paths and those paths in the affected files. The regression case uses that same trigger and expected disposition as its assertion and names a versioned target test file and a description.

  A `real-block` cites a current open stop, its refusal site and the rule supporting it. A `false-positive` gives the covered stops, reason and current runtime citation usable by the dismissal flow. A `stale-state` cites packet evidence of the change. A `needs-joe` states the unresolved question and the evidence available. Use explicit nulls and empty edit lists for inapplicable repair fields. Validate every reference supplied.

- [ ] **Decide in `server/overseer/corroborate.ts`.** Accept the frozen input, independently current facts, two stage outcomes and harness-owned reservation and launch facts. The caller supplies the selected ID and revision from `selectIncident`. In ledger fixtures, follow the read-only query pattern in `tests/unit/overseer/budgeted-run.test.ts:18` and read `reservations` for the incident across days, including attempts that failed, timed out, retained a hold or returned invalid output. Research and triage each have a stage slot within the same numbered triage round. `readStanding` supplies daily totals. Apply these rules in order and return the outcome and reasons.

  1. A candidate outside current selection, or a selected ID or revision mismatch, yields `needs-joe` with the eligibility reason. Verify the frozen packet body and input identity against the independently current packet and release facts. A corrupt or superseded common input makes both opinions unusable and goes to bounded fallback.
  2. Check each slot against its expected launch, role, incident, round, reservation, bound session, provider and evidence identity. Paired conclusions require distinct reservations and opposite providers. Resolve each subject reference by key and digest to the same open entry in `subjects.included` and each event ID to `events.recent`. Verify every range and file reference, including correction, affected and regression files. Mark an unsupported or superseded citation `forged-or-stale` and treat that opinion as missing before reading its verdict.
  3. Return `retain-block` for any verified open subject with `unsettledEffect` or a typed `hold`, `decision`, `merge-approval`, `prerequisite`, `pause`, `authentication`, `question` or `uncertain-effect`. Either valid `real-block` also yields `retain-block`, even with a missing peer. For an incident-wide proposal that claims coverage, require a nonempty open set, an included open count equal to `subjects.open`, and agreed coverage equal to that set. Omitted cleared history is acceptable. Incomplete open coverage goes to fallback.
  4. A valid opinion naming an unresolved authority prerequisite vetoes repair. Two independent valid `needs-joe` opinions yield `needs-joe`. Two independent valid opinions agreeing on `stale-state` or `false-positive` and their cited basis yield that proposal. The existing Office flow owns any later dismissal or settlement.
  5. Before admitting repair, check a multi-source open subject whose displayed wait is `retry` or `provider-wait` for a masked protected wait. For optional detail, the fixture supplies `id`, `revision` and `subjects` together from an independently obtained `Incident` snapshot. First require the detail incident’s `id` to equal both the selected ID from `selectIncident` and `packet.incident.id`. Require its `revision` to equal both the selected revision and `packet.incident.revision`. Take the `IncidentSubjectRecord` from that same snapshot’s `subjects`. Separately recompute `repairSubject(record)` using `server/incidents/subject-digest.ts` and compare its returned `subject` and `digest` with the corresponding fields on the same open entry in `packet.subjects.included`. Never trust a key or digest supplied pre-bound. Use `contributions` and any `carried` facts only after both the incident and stop checks pass. The existing incident detail read can supply the snapshot at later integration. Missing detail or failure of either check leaves the masked wait unresolved, including the case where the subject matches but the stop digest differs. Route these cases, a conflicting protected report or an opaque legacy aggregate to bounded fallback under rule 6 with repair blocked. Complete per-source facts that clear the ambiguity allow the ordinary gates to proceed. Return `admit-repair` only for two independent, current, high-confidence `harness-defect` opinions passing all coverage and authority checks. Both must affirm the incorrect refusal against the same distinct requirement and agree on the supported behavioral correction, file scope and regression case. Return the agreed case and evidence identities. Apply this rule to every guard change.
  6. Use the incident’s actual remaining stage slots. If a qualifying triage lacks only an available blind opinion, return `research` with the reason to obtain `second-opinion` round 1, including after triage round 2. Otherwise an inconclusive pair yields `research` when another triage slot is available and a blind opinion can still be obtained or a valid one already covers the identical input. This permits one remaining triage round to resolve disagreement. Return `needs-joe` when the necessary slots are spent, budget facts are unavailable, or the spent blind opinion is unusable on changed evidence. A correction the blind opinion still does not affirm after the final triage also yields `needs-joe`. Every proposed call requires transactional admission. A conclusive pair on the last legal calls remains eligible.
