## Qualification contract

- [ ] **Require evidence for each observation.** In `sandbox-qualification.ts`, enumerate the required probe IDs. Bind each observation to the run, probe, effective policy, and profile. Require a payload start marker and one structured terminal outcome. For each deny, require a successful same-operation positive control against a disposable target outside the sandbox and an operation-specific enforcement result inside it. Collect markers through output hooks so a rejection cannot erase startup evidence. Known setup failure before a confirmed start may report `sandbox-failed`. Missing start evidence means startup is unconfirmed. A rejected command, reported signal, cancellation, or zero exit without the expected terminal evidence cannot be successful. Refuse missing, duplicate, conflicting, wrong-profile, and inconclusive rows by name. Controls are dedicated fixture operations. A failed wrapped command has no retry or fallback.

- [ ] **Define the battery in 7b and run it only with fakes.** Specify these observations for later execution on the approved installation under the actual policy:

  - Confirm payload startup, exact argv round-trip, the expected cwd, a known snapshot read, and writes with read-back in `run.tmp` and `run.provider`. Check the payload’s effective `TMPDIR` and create a file using its ordinary temp-directory API.
  - Deny reads of sibling, runner-state, synthetic Office, and protected Claude and Codex configuration sentinels outside the isolated provider directory. Deny writes to the frozen snapshot, run root, sibling, policy file, and both shared temp spellings. Include replacement or removal of the disposable policy and snapshot sentinels and verify their original bytes afterward.
  - Test credential access independently using a uniquely identified synthetic item in a disposable test keychain and a successful noninteractive control for that item. Record only the outcome. A locked or missing item, a prompt, or an unavailable control is inconclusive. The base profile permits selected `securityd` and `SecurityServer` lookups, which makes the credential operation itself essential.
  - Use reachable, test-owned endpoints for direct and proxied network attempts, a separate loopback listener, a Unix socket, and a harmless launchd IPC query against a test-owned service through a permitted probe client. Confirm the appropriate policy or proxy refusal for each route. DNS failure, an absent listener, a proxy authentication error, or inability to execute `launchctl` cannot satisfy those checks. Empty domains still leave the runtime’s own HTTP/SOCKS loopback proxy reachable. Verify what it can forward and record the remaining IPC surface. Any conflict with a required denial leaves the profile unqualified. [Tagged proxy manager](https://github.com/anthropics/sandbox-runtime/blob/v0.0.83/src/sandbox/sandbox-manager.ts)
  - Record the parent’s filesystem footprint and confirm the payload, owned group, and proxy listener have ended on success, failure, and interruption. The Darwin parent keeps proxy state in memory. TLS and credential-mask temp writers are conditional and those features are disabled here. Check the effective payload’s Java agent reference against the verified installation without recording proxy tokens. A budget timeout can return while cleanup is pending.
  - Record nested Seatbelt separately. A working standalone control and a specifically observed nested refusal establish `unsupported`. A successful nested check must demonstrate an inner restriction on an operation the outer policy permits. The reported exit 71 on Darwin 24.3 is host evidence for the refusal on record. It does not establish another host’s or provider binary’s result.

- [ ] **Gate the exact reader or writer profile.** `qualify` may report a complete outer battery and a separate `innerSeatbelt` outcome. `profileEligibility` requires both a matching host outer receipt and a matching inner receipt from the actual provider nested under that policy.
