# Trim the Office unit suite

**Start with redundant recovery scenarios and real-time waits.** Two recovery tables alone can go from **48 full-workflow cases to 13**, while retaining direct checks for every input they validate. Three other tests can shed roughly **23 seconds of real waiting** without changing the production retry policy.

### Suite health

I scanned all **886 unit test files** across **23 domains**, then inspected the largest suites, slowest cases, likely duplicates, and their production call sites. The comparable macOS CI run passed **7,640 of 7,640 tests in 13m 40s**. The test tree matched the audited checkout at `726a272`. Vitest attributed **54%** of runtime to imports and **39%** to test execution. There were **137 single-test files**, so splitting large files indiscriminately could make the suite slower. Line and branch coverage percentages were unavailable in the current configuration. [CI baseline and timings](https://github.com/JFusco/the-office/actions/runs/45486905992/job/138774705725)

### Delivery and acceptance

1. Land the deletions and timer changes first, followed by the recovery-table refactor and Effects coverage. These changes can use the current production interfaces.
2. Demonstrate that representative regressions still fail the retained tests: a sixth provider read, a second PR creation, acceptance of malformed provider data after the worker returns, a changed intent returning an old receipt, and removal of the startup keep-alive configuration.
3. Run the focused suites, type-check, and complete the repository’s `pnpm build` and `pnpm test` gates. Compare the updated macOS CI run against the baseline and report **net cases removed, full-workflow cases removed, and measured runtime** separately. The 48-to-13 estimate counts expensive workflow cases; the direct provider checks still count toward the suite total.
