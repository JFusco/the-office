## Shared command runner

- [ ] In `server/workers/spawn-command.ts`, add `replaceEnv?: Readonly<Record<string, string>>` to `CommandOptions`. In `spawnCommand`, keep the abort check first. Before `liveReach` or any spawn, reject simultaneous defined `env` and `replaceEnv`, including two empty maps, with `CommandFailure('A command cannot both merge and replace its environment', 'other', false)`. For replacement under an active Node permission model (`process.permission !== undefined`), also throw a specific `CommandFailure` with `dispatched` false. Both refusals precede `onSpawn`.
- [ ] At the existing spawn call, select replacement by presence, including `{}`. Copy only own enumerable string entries into a private, null-prototype `NodeJS.ProcessEnv`. Give that map its own `NODE_V8_COVERAGE` entry set to `undefined` before copying so an explicit caller value wins. Node 24.14.0 skips the undefined entry during serialization and otherwise can copy the parent's coverage value. Refuse empty names and names containing `=` before dispatch. Keep Node's NUL validation. Empty values and `=` in values are valid.
- [ ] Use the existing override merge and default environment expressions for other calls. Keep the live-provider guard keyed to the parent's `process.env.VITEST` and retain the existing lifecycle hooks. Document replacement on `command` in `server/workers/process.ts`. Its options already reach `spawnCommand` directly or through `server/github/metered-runner.ts`, whose failure accounting starts at `onSpawn`. Worker callers use absolute executable paths. Unix bare-name lookup uses the supplied `PATH` or the system fallback when it is omitted.
