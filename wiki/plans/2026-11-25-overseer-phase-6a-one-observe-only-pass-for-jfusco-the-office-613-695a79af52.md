# Overseer phase 6a — one observe-only pass for JFusco/the-office#613

Deliver one independently invoked pass that reads Office health and research incidents over loopback, keeps at most one incident in flight and records outages in runner-owned files. Selection is the only stage advance. Phase 6b owns budgets and the private Store, 6c owns the launcher, deadline, code pin and installation, and 6d owns forwarding and notices. The 6a grant covers local runner writes and the two Office GETs. Deployment and post-merge cleanup belong to the separate session.

## Entry, paths and ownership

- [ ] Add `server/overseer.ts` as a Node-built-in-only bootstrap. Put `requireRunnerRoot(env)` here so it can validate the explicit entry root before loading any project module. Guard execution on direct invocation so the CLI can reuse the validator. Add `resolveCliRoot(env)` in `server/overseer/commands.ts`. Only the CLI supplies `~/Projects/the-office-overseer` when the variable is unset. An explicitly empty or relative value is invalid in either caller. Pass the validated directories to the machine so its imports do not cycle back through the executable entry.
- [ ] Validate the physical path before the first write. Resolve each prospective directory through its nearest existing ancestor with `realpath`, then append its missing components. Use path-component containment. Compare against both the inherited `OFFICE_DATA_ROOT`, resolved as `server/office/config.ts:6` resolves it, and the running checkout's `.local`, derived from the entry location. Refuse a runner root equal to or inside either protected root, or beneath an Office marker (`office-control.sqlite`, `controller-pin.json` or `deployments/`). Check the supplied and resolved ancestry. Refuse overlapping private write directories, dangling links, inconclusive lookups, and an existing `control`, `journal`, `state` or `state/office-data` that is a link or is not a directory. Check missing components before creation and verify directories after creating them with mode 0700.
- [ ] In `server/overseer/config.ts`, have `runnerPaths` name `control/STOP.json`, `control/pause.json`, `control/pass.lock`, `control/pass.lock.reclaim`, `journal/failures.jsonl`, `state/runner.json` and `state/office-data`. Keep the draft defaults of one incident, a 120,000 ms launcher interval, 30,000 ms per HTTP attempt, 8 MiB per response, a 300,000 ms outage threshold with two failed passes, and 1,000 journal entries. The entry executes once.
- [ ] Reject an invalid root or verb other than `pass` with exit 2, a stderr reason and empty stdout before any project import. Assign the validated private Office path to `process.env.OFFICE_DATA_ROOT`, replacing the inherited value, then dynamically import `./overseer/machine` and `./overseer/pass`. In `machine.ts`, capture the actual environment value at module evaluation and expose it as `officeDataRoot` on the entry's printed result. Build the machine with validated paths, `officeReader`, `systemClock.now`, a pass UUID, PID, liveness check and log sink. Validate the Office URL before runner writes. Create `state/office-data` only after acquisition succeeds.
- [ ] Implement `acquirePassLock` in `single-flight.ts` using the ownership protocol of `server/release/deploy-lock.ts#acquireDeployLock`, with runner paths and `{ pid, pass, at }` diagnostics. Bootstrap the private control directory as needed. Read and validate the owner, take the create-exclusive `.reclaim` guard for both fresh acquisition and takeover, then reread. Reclaim only the identical observed dead owner. Treat `ESRCH` as dead, `EPERM` as live and an inconclusive check as a refusal. Publish a complete mode-0600 owner using `writeDurableIfAbsent` for acquisition or `writeDurable` for confirmed takeover. Refuse a live or unreadable owner and a retained guard even when the owner file is absent. Release only the matching owner, safely on repeated calls, and remove only the guard the acquisition obtained. A refused pass exits 3 with a reason and leaves runner data untouched. Release acquired ownership in `finally`.

## Local controls, state and journal

- [ ] Implement `readHalt`, `writeRunnerStop`, `pauseRunner` and `unpauseRunner` in `kill-switch.ts`. Read STOP first, then pause. Use `readBoundedNoFollowSync` from `server/store/owned-artifact.ts` for bounded artifact reads, distinguishing confirmed absence from invalid, linked, oversized or unreadable files. A valid pause yields `paused`. STOP and unreadable controls yield `stopped`. Publish STOP and pause with `writeDurableIfAbsent`, preserving the first reason. Unpause unlinks only `control/pause.json` and tolerates its absence. Only a person clears runner STOP.
- [ ] In `runner-state.ts`, validate the versioned `runner.json` with Zod and save it with `writeDurable`. Keep `inFlight`, `outage`, an optional pending journal intent, the last pass, and separately dated `observation.health` and `observation.incidents`. A fresh root starts empty. An unreadable or invalid state file causes first-reason STOP and a printed `stopped` result. Return before any state save, including a `lastPass` update. Surface a write or sync failure that prevents durable reporting as a nonzero error.
- [ ] Implement `readFailures` and `appendFailure` in `failure-journal.ts`. Each newline-terminated UTF-8 JSON record has version 1, ID, kind, time, episode, sanitized detail of at most 500 characters, and bounded evidence. Keep only the relevant sample times and bounded service identity/hash in outage evidence. Validate complete records and bound reads to the supported record and journal sizes. Expose the complete prefix and a `torn` flag for an unterminated last line. A torn tail, malformed complete record, conflicting ID or unreadable journal preserves the bytes, refuses appends and produces STOP. Status reports the condition. For an append, open without following links, verify a regular single-link file on the descriptor, check the complete write length, sync the file and sync the directory on creation.
- [ ] In `service-down.ts`, implement pure transitions using one sample per pass. A failed validated health read opens an episode using that pass's UUID, or increments the existing episode. Persist `since`, failure count, last failure time, sanitized reason and whether down was journaled. Admit down only when both inclusive thresholds hold. Use `overseer:service-down:<episode>` and `overseer:service-restored:<episode>`. A successful validated health read closes the episode even if it reports a held fence or the subsequent list fails. A short gap gets a pass note. A journaled gap gets exactly one restoration.
- [ ] Commit each journal transition under the pass lock. Serialize the complete event once. First durably save its exact line and intended next outage state in `runner.json`. On an intact journal, compare an existing ID's complete content before checking capacity. An identical record satisfies the append. A new down requires two free slots, one for its restoration. A new restoration requires one. Append the saved bytes when absent, ensure publication is synced even on recovery, then durably apply the saved next outage state and clear the intent. At capacity retain the intent, record first-reason STOP and report `stopped`. Preserve every journal record for forwarding. At the start of each pass, reconcile any saved intent by this same procedure before a GET. A conflict or damaged journal keeps the intent available for inspection.

## Office reads and the pass decision

- [ ] In `config.ts`, accept `OVERSEER_OFFICE_URL` as an HTTP origin only, defaulting to `http://127.0.0.1:4318`. Allow `127.0.0.1`, `localhost` and `[::1]` with an optional port. Reject credentials, a non-root path, query or fragment. In `office-client.ts`, expose only `health()` and `researchIncidents()` from `officeReader(base, request, defaults)`. Use fixed paths, explicit `GET`, an empty request body, `redirect: 'error'` and an abort signal covering the response body. Check declared length and actual chunk byte lengths, cancel oversized bodies, and apply the same limit to error bodies. Require a successful status and valid JSON. Retry the same GET once only for a transport error whose cause code is `ECONNRESET`, `EPIPE` or `UND_ERR_SOCKET`. Sanitize diagnostics before limiting them to 500 characters.
- [ ] Parse `/api/health` with `ServiceHealth` from `server/release/service-http.ts`. Read optional release status and commit from the original response object. An explicit `fence.status` of `invalid` is a valid health observation. Parse `/api/incidents?research=1` as `{ incidents }` using the fields of `src/contracts/incidents.ts`. Validate every row's ID, lifecycle state, revision, cause source, research eligibility and nullable research time, and derive the open count from `subjects[].status`. Reject the whole read on an invalid row. Use the existing research query as supplied by `incidentsRoute`.
- [ ] In `select-incident.ts`, operate on the full validated result. An eligible incident has `research.eligible` true, a source other than `runner`, and state `observed`, `triaged` or `recurred`. Lifecycle state determines whether a repair is active. A historical `repair` on a recurred incident is compatible with selection. Keep a qualifying in-flight ID and refresh its observed revision. Otherwise report its release with `not-research-eligible`, `runner-source` or `state:<state>` as applicable. Choose at most one replacement by earliest research time, null last, then ascending ID. Apply the 50-summary cache limit afterward, retaining the selected summary when present.
- [ ] In `pass.ts`, acquire ownership, initialize the private data directory, read state, check journal integrity and reconcile pending local work. Then read halt before the first GET. On an initial halt, record only `lastPass` after any recovery already due. On failed health, apply the outage transition, keep both cached samples and `inFlight`, and record `service-down` with `cachedHealthAt` and `cachedIncidentsAt`, nullable when absent. On successful health, update `health.at` at observation time and settle any restoration. A held or invalid fence yields `fenced` and skips the list. A failed list yields `read-failed`. Both paths keep the previous incident summaries, their original `incidents.at`, and `inFlight`.
- [ ] Date and cache a list only after a complete successful read. Recheck STOP and pause after awaited reads, immediately before selecting or releasing an incident. A halt at that decision records `stopped` or `paused` and preserves `inFlight`. Keep the decision and state publication synchronous from that check. Otherwise save `observing` or `idle`. For valid state, durably save the pass UUID, start/end times, outcome and bounded detail, plus `selected`, `kept`, `released` and cache times where applicable. Print the recorded result as the last stdout line and exit 0. Lock refusals and failed persistence use the distinct exits above.
