# Feature planning and engineering lessons

Feature Discovery produces a reviewable brief. Feature Planner turns an approved brief into implementation-ready tickets with acceptance and verification requirements. The original two-stage model landed in PR #39.

Harper's knowledge loop began as a broader continuous-learning plan. Later deliveries reduced it to demand-driven lessons, retained evidence, and explicit curation outcomes. Use the knowledge-loop document for the current contract and the archived plan for the historical proposal.

Harper hands each blocker follow-up to Morgan as one read-only diagnosis at a time, and sends another only when what is due changes. A stopped maintenance run is keyed on its own stop (status, stage and end time), not on its error text: each read-back rewrote that text in new words and earned another paid diagnosis of the same block. Joe chose one diagnosis per stopped run on 2026-11-25, even when a later read-back finds a different write unverified: Morgan's read-back is that diagnosis. A changed prerequisite reaches Morgan through the run that replaces it ([maintenance stop key](../journal/2026-11-26-maintenance-handoff-stop-key.md)).
