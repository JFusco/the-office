# GitHub delivery and recovery

The Office gives models implementation and review decisions. The harness owns candidate worktrees, GitHub and board mutations, merge readiness, and closeout. Durable Effects preserve mutation intent and reconcile uncertain outcomes through provider read-back.

The initial hands-off rollout introduced this division for Brain. Later changes extended retry and recovery without giving abandoned model runs authority to publish. The simplification in PR #212 and deterministic intake in PR #335 consolidated work around the ordinary delivery path. Approved prerequisites are evaluated as structured gates. A reviewed PR that starts to conflict after its readiness review stopped is refreshed by the harness on the next observation, under the same eligible-head rule, budget and exclusions as any conflict refresh, with the stopped verdict kept in the job's steps ([journal](../journal/2026-11-26-refresh-stopped-review-conflicts.md)). A stopped job those refresh rules refuse on local state alone costs that sweep no GitHub read ([journal](../journal/2026-11-26-stopped-sweep-local-eligibility.md)). A verified saved writer that declares prerequisites is adopted without a replay when its paid-run count is `0` or not reported (`null`); a reported positive count prevents adoption.

The Office adopts eligible Context Wiki reconciliation PRs on hands-off GitHub projects with a configured board, unless an explicit `autoAdopt` list leaves wiki-sync out. It validates the bot account, commit history, and Markdown and graph-data scope. A canonical wiki PR title may carry exactly one trailing ` [skip release]` marker, for repositories whose release policy needs it; no other title variation qualifies ([journal](../journal/2026-11-25-wiki-sync-skip-release-titles.md)). Qualified wiki PRs proceed directly to required current-head GitHub checks and repository merge rules. A conflicted adopted bot PR (wiki-sync, Dependabot or Pin Courier) is redone by its own bot, once per conflicted head and never by an Office commit; its qualified replacement head merges on the ordinary path, and a numbered wiki PR whose regeneration left it unchanged is closed as superseded only on a proof that its target already contains it ([journal](../journal/2026-11-26-bot-pr-conflict-redo.md)).

Office writes are moving to the Office's own GitHub App identity one route at a time. Every route stays on the operator's login until a recorded qualification and explicit activation say otherwise, a route that was activated holds rather than silently writing as the operator, and a rollback must name its activation. See [the identity foundation](../journal/2026-11-26-app-identity-foundation.md). An issue-comment trial needs the saved POST ID, an exact actor and body read-back, and one matching marker in the complete issue conversation. A marker-only recovery can settle delivery while leaving the trial unqualified. See [the issue-comment proof](../journal/2026-11-27-app-issue-comment-qualification.md). One approved trial is sent by `pnpm office app-trial` with an exact public packet. A rejected trial is spent and never gets a successor, and the live receipt must be in the durable project store. See [the trial command](../journal/2026-11-28-app-trial-comment-command.md). A pull request conversation comment is proved separately. It uses the real `github-pr-comment` operation and the PR comment adapter it shares with Dependabot redo, with the PR's head and base bound in the approved digest. See [the PR comment trial](../journal/2026-11-28-app-pr-comment-trial.md).

Dependency-bot PRs (Dependabot, pin-courier, wiki-sync) are [adopted automatically by default](../journal/2026-11-26-auto-adopt-defaults.md) on hands-off GitHub projects with a configured board; an explicit `autoAdopt` list narrows or disables it.

A delivery job stopped by a transient GitHub failure is [retried by the harness](../journal/2026-11-27-transient-github-retries.md), including a read-back-first retry of a hands-off draft; an uncertain write is only ever read back, never resent.

An opted-in project (CMS by default) [refuses to push a `[skip release]` commit that changes the npm package](../journal/2026-11-27-release-marker-check.md). Unmarked pushes stay free of npm and extra provider reads, undecidable coverage stops for a person, and an ordinary unpublished writer gets at most two messages-only corrections that the harness applies. The CI commit-message repair push remains outside the check.
