# Feature discovery and planning

Open **Features** on the delivery floor, choose **New feature**, and describe the problem. Existing goals and tickets also have an explicit planning action. Casey researches a frozen source baseline, asks up to three related questions, and maintains the brief. Confirm the brief to ask Alex for a technical plan.

The installed `review-plan` workflow independently researches and reviews the complete plan. Each helper stage uses a separate scheduler turn. Questions and approval release worker capacity. The Review view retains the helper handoff; it does not manufacture a Sam verdict.

**Approve & start delivery** authorizes the displayed brief, accepted plan, ordered ticket manifest and provider changes. GitHub successors wait for verified merge and closeout. CEC successors wait for verified staging acceptance. Normal implementation requires independent review; the existing conflict-only repair exception remains in force.

## Revisions and recovery

Correcting a decision creates a new planning lineage and invalidates authorization for unstarted work. Started tickets keep their original approval. Separate follow-up features carry changes to started scope. Linked features connect initiatives across projects without sharing approvals.

Answer drafts are stored in this browser by project, feature, round and question. Registered document artifacts retain their full contents and digests. A repeated request cannot create a second operation; stale or conflicting requests fail.

A blocked publication is reconciled through saved Effects and provider read-back. An uncertain creation is never resent. The visible admission fence protects the project until the new ticket identity is reserved; each feature ticket remains held until the complete publication has been verified. Existing project holds and release controls continue to apply.

Pause stops planning and new admissions. It does not revoke already-started delivery ownership. Reader recovery waits for owned process termination before recording one replacement. Helper recovery uses its canonical run, receipts, frozen configuration and supported recovery commands; it does not reset review budgets.

## Provider and source contracts

Both configured GitHub projects and CEC use the existing connections. GitHub publication validates repository permissions, labels, assignment and configured board placement. CEC discovers base issue types and required fields with TWG; board scope provides the filter used for membership read-back. Unsupported required fields remain a visible blocker.

Discovery and plan review share an isolated source checkout. Approval observes the remote target and compares relevant file content, modes, presence and repository instructions. An unrelated commit alone does not invalidate the plan. Source changes require fresh discovery against a new baseline.
